# Contributing Guidelines

Thank you for your interest in contributing to this project.

## How to Contribute

Follow these steps to contribute:

1. Fork the repository.
2. Clone your forked repository.
3. Create a new branch.
4. Make the required changes.
5. Test your changes.
6. Commit your changes using a meaningful commit message.
7. Push your branch to GitHub.
8. Create a Pull Request.

## Branch Naming Convention

Use the following naming conventions:

- `feature/feature-name` - For new features
- `bugfix/bug-description` - For bug fixes
- `docs/documentation-update` - For documentation changes

## Commit Message Convention

Use clear and meaningful commit messages.

Examples:

- `feat: add new feature`
- `fix: resolve issue`
- `docs: update documentation`
- `chore: update repository structure`

## Code and Documentation Guidelines

- Keep documentation clear and simple.
- Use meaningful names for files and branches.
- Test changes before creating a Pull Request.
- Do not commit unnecessary files.
- Keep the repository structure organized.

## Pull Request Guidelines

Before submitting a Pull Request:

- Explain what changes were made.
- Mention how the changes were tested.
- Ensure the documentation is updated when required.
- Follow the project's branch and commit conventions.

## Reporting Issues

Use the GitHub issue templates to report:

- Bugs
- Feature requests

Thank you for contributing!
